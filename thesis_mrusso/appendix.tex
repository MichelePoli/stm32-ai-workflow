\section{Compression Benefits}

INT8 quantization applied via STEdgeAI provides approximately:
\begin{itemize}
    \item \textbf{RAM Reduction}: 75\% (4× compression factor)
    \item \textbf{Flash Reduction}: 75\% (4× compression factor)
    \item \textbf{Speed Improvement}: 2-3× faster inference on Cortex-M cores without FPU
    \item \textbf{Accuracy Loss}: Typically $<$ 2\% on standard benchmarks (CIFAR-100, ImageNet)
\end{itemize}

Example: MobileNet V2 0.35 requires 600 KB RAM / 1.1 MB Flash in FP32 format (incompatible with F401), but only 150 KB RAM / 280 KB Flash after INT8 quantization, enabling deployment on L476 and H743 platforms.

\section{Implementation Integration}

This compatibility matrix informed the design of the automated \texttt{check\_resource\_constraints()} function in Workflow 2 (Section~\ref{sec:ai_workflow}), which:
\begin{enumerate}
    \item Parses STEdgeAI analysis reports to extract RAM/Flash usage
    \item Compares against target MCU limits using \texttt{get\_mcu\_limits()} lookup table
    \item Routes to high compression if overflow $<$ 4×, or rejects model if overflow $>$ 4×
\end{enumerate}

\section{STM32 MCU Part Numbers Reference}
\label{app:mcu_part_numbers}

This section provides a full reference of STM32 microcontroller part numbers for direct use with STM32CubeMX CLI commands. Unlike board selectors (e.g., \texttt{NUCLEO-H743ZI}), which may not be available in all CubeMX database versions, part numbers directly reference the microcontroller chip and are universally recognized.

\subsection{Part Number Naming Convention}

STM32 part numbers follow the pattern: \texttt{STM32[Family][Series][Variant][Package]}, where:
\begin{itemize}
    \item \textbf{Family}: F (Foundation), L (Low Power), H (High Performance), U (Ultra-Low Power), N (NPU)
    \item \textbf{Series}: Numeric identifier (e.g., 401, 476, 743)
    \item \textbf{Variant}: Flash/RAM capacity code (e.g., R=64KB, Z=192KB)
    \item \textbf{Package}: Physical package type with suffix (e.g., Tx=LQFP64, Hx=TFBGA)
\end{itemize}

\subsection{CubeMX CLI Usage}

Part numbers enable direct MCU loading in STM32CubeMX script mode, bypassing potential board database issues:

\begin{verbatim}
load STM32H743ZITx
project name MyProject
project toolchain "STM32CubeIDE"
project path /tmp/project
project generate
exit
\end{verbatim}

This approach is particularly useful in automated workflows where board definitions may be missing or outdated in the installed CubeMX version. The automated fallback mechanism implemented in this work (Section~\ref{sec:firmware_workflow}) leverages part numbers when board-based initialization fails.
