Good morning everyone. I'm Michele Russo and today I present my thesis: "From IDE to Edge: A Cloud-Native Multi-Agent Framework for Automated Edge AI Deployment on STM32".

[Slide 2: The Core Problem]
Right now, a profound disconnect exists in the tech industry. AI engineers write Python, deploy cloud servers, and train LARGE neural networks. Meanwhile, embedded systems engineers write C, fight strict memory limits, and program bare-metal STM32 hardware. 
Pushing neural networks to run locally on these resource-constrained microcontrollers is known as Edge AI. 
And right now, it is a highly inefficient process. Developers must master a fragmented toolchain: STM32CubeMX for hardware, STEdgeAI for model conversion, custom Python scripts for hyperparameter optimization, and manual C-code integration. 
My tests show this manual pipeline takes an expert over 4 hours. Most of that time is wasted navigating dense GUIs, searching datasheets, writing repetitive code, and debugging tiny misconfigurations.

[Slide 3: The Multi-Agent Solution]
My thesis asks: what if an AI assistant could handle this tedious toolchain instead? To answer this, I built an end-to-end, multi-agent framework. Instead of clicking through interfaces, the developer just talks to their IDE. They can say: "Generate an STM32H7 project, find a small MobileNet model, optimize it, and put it in my C code."

[Slide 4: Architecture & Orchestration]
The system relies on Multi-Agent Orchestration using LangGraph. I designed it as a directed graph divided into specialized branches. One branch handles Firmware Generation by controlling the STM32CubeMX CLI without a GUI. 
Another Customization branch writes Python scripts to fine-tune networks or run hyperparameter searches. 
A Web Search branch reads current documentation straight from the internet.
To ensure low latency and horizontal scalability, I split the agent logic from the heavy LLM inference. All LLM requests go to a centralized NVIDIA Triton Inference Server. Triton handles dynamic model swapping and shares GPU memory across users. This decoupling lays the groundwork for a fully scalable Kubernetes deployment, allowing multiple developers to share the same hardware without bottlenecking.

[Slide 5: IDE Integration & Human-in-the-Loop]
We also didn't force developers into a web app. I built a custom Visual Studio Code Extension. The assistant sits right inside the editor. It uses asynchronous streaming so the IDE never freezes during heavy tasks. At critical moments, like right before starting a long training job or running the automated EdgeAI compiler, the system stops and asks the user for permission in the chat. So the developer stays in control.

[Slide 6: Automated Workflows in Action]
Let's look at how the framework actually performs.
First, Information Retrieval. LLMs are notorious for hallucinating technical specifications. To fix this, I built a live web search agent using DuckDuckGo. When the user asks a technical question, the agent autonomously queries the internet, extracts the content from the actual result pages, and constructs an answer grounded in the retrieved documents. To objectively measure its reliability, these answers are evaluated programmatically using the DeepEval framework to calculate hallucination rates and faithfulness to the source material.
Second, Firmware Generation. A developer usually navigates around 15 manual configuration steps in CubeMX to set up clock trees and peripherals. My framework uses pre-seeded templates to skip the GUI entirely. It translates the user's plain English into the correct headless command, building the C project in the background.

[Slide 7: Neural Network Customization & NNI]
Third is Neural Network Customization. Pre-trained models are rarely ready for production out-of-the-box. Instead of writing tedious setup code, the developer can simply ask the assistant to modify the network's architecture in plain English. The agent analyzes the user's intent and automatically rewrites the Keras code to apply one or more among these five main categories of modifications: freezing specific segments of the backbone, adjusting the final output layer for a custom number of classes, injecting dropout layers to prevent overfitting, setting custom learning rates, and even appending new dense layers. 
Furthermore, if the user asks for hyperparameter optimization, the system fully integrates with Microsoft's Neural Network Intelligence, or NNI. Setting up NNI manually is notoriously complex. You have to write a custom trial script, define a search space in JSON, and configure a manager. Instead of forcing the developer to do this, my Customization Agent dynamically writes the entire NNI experiment from scratch. It generates the `trial.py` file, defines the search boundary for learning rates and batch sizes, and launches the tuning job automatically. The developer simply asks for "optimization" and waits for the best model to emerge.
Finally, after a model is optimized, the system runs an automated hardware validation using the STM32EdgeAI compiler. It analyzes the network's exact RAM and Flash requirements against the physical limits of the target microcontroller. If the model is too large, the agent autonomously attempts to escalate the compression level. If it still exceeds the hardware limits, the orchestrator interrupts the workflow, warns the developer, and offers two choices: downgrade to a lighter model, or swap the underlying hardware for a more powerful STM32 board. This ensures the workflow never produces a project that is mathematically impossible to compile.

[Slide 8: Benchmarks & Productivity Gains]
A developer tool only matters if it actually saves time, so I benchmarked the automated workflow against experienced developers.
The end-to-end AI deployment dropped from about 4 hours to just 20 to 30 minutes. That is a 9x speed increase.
If we break it down:
CubeMX Project Setup went from 20 minutes to 30 seconds. That’s a 40x speedup just by cutting out the GUI.
Model Discovery showed a 24x speedup, replacing hours of GitHub searching with a few minutes of automated scanning.
And that NNI Experiment Setup we just talked about? It usually takes nearly an hour of writing configs and scripts. The agents did it in 1 to 2 minutes—a 30x speedup.

[Slide 9: Validation & Reliability]
I also tested the generated code itself. In a test run fine-tuning MobileNetV1 for a custom 132-class dataset, the agent accurately translated the user's high-level request for anti-overfitting measures into functional Keras code, correctly injecting dynamic dropout and freezing layers. 
The resulting model hit 98.1% validation accuracy on a set of 5,000 images.
Finally, I evaluated the web search agents using the DeepEval framework to measure reliability. Across multiple queries, the system scored an average Contextual Relevancy of 75% and kept hallucination rates remarkably low, between 4% and 14% depending on the task. When given strict procedural tasks, the agent scored a perfect 1.0 on Faithfulness, meaning it stuck entirely to the retrieved technical manuals.

[Slide 10: Conclusion & Future Works]
To conclude, this framework proves that multi-agent orchestration works for embedded development. We successfully combined headless CubeMX generation, Triton-backed LLMs, and NNI optimization into a single IDE extension. 
Looking ahead, because we deliberately decoupled the agent logic from the Triton servers, the next logical step is migrating this architecture to Kubernetes. 
This will allow enterprise teams to share hardware resources efficiently.
But looking at the current data, shrinking a 4-hour deployment down to 30 minutes demonstrates that deploying AI on microcontrollers no longer requires a rigid, manual process. The framework provides a faster, scalable, and highly automated alternative.
