\section{Human-in-the-Loop Implementation}
\label{sec:hitl_impl}

The framework implements Human-in-the-Loop controls through LangGraph's \texttt{interrupt()} primitive, enabling workflow suspension at critical decision points.

\subsection{Interrupt Mechanism}

LangGraph checkpoints state after every node execution. When a node calls \texttt{interrupt()}, execution pauses and control returns to the API server:

\begin{lstlisting}[language=Python, caption={Interrupt-based approval gate}]
# From workflow1_firmware.py
def decide_continue_to_ai(state, config):
    # Suspend execution and request user input
    user_response = interrupt({
        "type": "decision_request",
        "message": "Firmware generated. Continue with AI model selection?",
        "options": ["yes", "no", "skip"]
    })
    
    # User responses are classified via LLM
    llm_parser = get_llm(config, structured_schema=DecisionExtraction, temperature=0)
    result = llm_parser.invoke([
        SystemMessage(content=decision_extraction_instructions),
        HumanMessage(content=user_response)
    ])
    
    if result.continue_to_ai:
        state.route = "ai_flow"
    else:
        state.route = "END"
    
    return state
\end{lstlisting}

Upon receiving user input, the workflow resumes from the exact checkpoint where it suspended, preserving all state variables.

\subsection{Approval Gates vs. Steering Inputs}

The framework distinguishes two HITL patterns:

\subsubsection{Human-as-Gate}
Binary approval for risky operations (e.g., firmware flashing, model deployment):

In this pattern, the workflow automatically suspends immediately before executing any high-risk action. The user is then granted the opportunity to thoroughly review the proposed operation and must provide an explicit ``approve'' or ``reject'' command to proceed. Typical examples of these critical gates include confirming the continuation to the AI workflow after firmware generation, accepting a specific neural network model or requesting a broader search during model selection, and granting final approval to deploy the optimized model after NNI completion.

\subsubsection{Human-as-Instructor}
Natural language steering to modify workflow direction:

\begin{quote}
    User: \textit{"Actually, I want a smaller model"}
\end{quote}

The system reclassifies this input using structured extraction and updates \texttt{MasterState}:

\begin{lstlisting}[language=Python]
result = llm_classifier.invoke(user_input)
# result.intent = "change_model_size"
# result.target_size = "small"

state.model_size_preference = "small"
state.route = "search_model"  # Return to model discovery
\end{lstlisting}

This enables flexible, conversational control over the MLOps pipeline without predefined menu options.

\subsection{State Persistence and Resume Logic}

LangGraph stores checkpoints in a \textbf{Redis} database using a hierarchical key structure. Each checkpoint is serialized as a MessagePack or JSON payload:

\begin{verbatim}
checkpoint:{thread_id}:{checkpoint_id} -> {
    "v": 1,
    "ts": "2023-10-27T10:00:00Z",
    "channel_values": {
        "messages": [...],
        "firmware_project_dir": "/path/to/project",
        "route": "ai_flow"
    },
    "parent_config": { ... }
}
\end{verbatim}

The resume process begins when the client sends the user's input via the API (\texttt{POST /threads/\{thread\_id\}/runs}). Upon receiving this request, LangGraph retrieves the latest stored checkpoint corresponding to the specific \texttt{thread\_id}. It then selectively deserializes the \texttt{MasterState}, injects the new user input directly into this state configuration, and smoothly resumes continuous execution from the next designated node in the computational graph.

This architecture supports multi-hour workflows (e.g., overnight NNI experiments) with continuous resume capability.

\subsection{Actionable Reporting and Synthetic Summaries}

A key UX improvement implemented to improve high-level decision making is the transition from raw log introspection to \textbf{Synthetic Actionable Summaries}. Traditional toolchain outputs from CubeMX or STEdgeAI can be hundreds of lines long, containing technical noise that obscures critical failures.

The orchestrator now implements heuristic-based log parsing after each tool execution. Instead of presenting the raw output, the agent extracts a 1-line summary (e.g., \textit{" Project generated successfully (STM32H7, 4 peripherals enabled)"} or \textit{"WARNING: Memory Overflow: Flash required 3.2MB/2MB"}). These summaries are stored in the \texttt{MasterState} and used to build context-aware prompts for the user during interrupt points, significantly reducing the cognitive load required to guide the autonomous agent.
