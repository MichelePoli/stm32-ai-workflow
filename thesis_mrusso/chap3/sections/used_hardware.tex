\subsection{Hardware Employed}
\label{sec:used_hardware}

The development and evaluation of the Agentic Framework spanned two distinct hardware environments, reflecting the shift from local prototyping to scalable production deployment.

\subsection{Local Prototyping Environment}
Initial development and unit testing were conducted on a workstation equipped with an \textbf{NVIDIA RTX A4000} GPU, featuring 16~GB of dedicated VRAM (GDDR6 with ECC), operating with driver version 575.57.08 and CUDA version 12.9.

The 16~GB VRAM buffer was sufficient for deploying a single quantized Large Language Model via \texttt{Ollama} (Mistral-7B for orchestration, GPT-OSS-20B for code-completion) and running the LangGraph agent loops entirely on local hardware. This setup kept latency low and avoided cloud API dependencies during early development. The limitation emerged under multi-model concurrency: loading a second 7B model simultaneously exhausted available VRAM, forcing sequential load/unload cycles that eventually caused process crashes during shared-GPU scenarios.

\subsection{inNuCE Lab Heterogeneous Prototyping Platform (HPP) Cluster}
To handle production workloads and multi-user stress testing, the core inference engine migrated to the \textbf{inNuCE Lab Heterogeneous Prototyping Platform (HPP)}. The cluster node used for this project is equipped with an \textbf{NVIDIA A40} GPU, featuring \textbf{45~GB} of dedicated VRAM (46068~MiB), operating with driver version 580.95.05 and CUDA version 13.0. The GPU has a rated TDP of 300~W.

This expanded hardware was necessary to deploy the \textbf{NVIDIA Triton Inference Server}. The 45~GB VRAM capacity allowed multiple heavyweight models (such as Mistral and \texttt{gpt-oss-20b}) to remain resident in memory simultaneously without triggering destructive load/unload cycles. Delegating LLM execution over the network to the HPP hardware freed the local workstation CPU and RAM entirely for LangGraph orchestration logic and memory-intensive fine-tuning tasks.
