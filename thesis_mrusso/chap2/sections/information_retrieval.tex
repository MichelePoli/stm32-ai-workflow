\section{Information Retrieval and Retrieval-Augmented Generation}
Information Retrieval (IR) constitutes the backbone of intelligent systems that require access to dynamic, domain-specific knowledge beyond their training data. While traditional IR relied heavily on lexical matching techniques, such as BM25, which ranks documents based on keyword frequency, these methods struggle to capture the semantic intent behind a technical query \cite{Manning2008Introduction}. In the context of Edge AI deployment on STM32, where specifications are scattered across datasheets, forum discussions, and evolving software documentation, the ability to retrieve information based on meaning rather than just syntax is non-negotiable.

\subsection{Semantic Search and Vector Embeddings}
The shift from keyword-based to \textit{semantic} search is driven by the use of \textbf{Embeddings}, dense numerical vectors that map textual concepts into a high-dimensional geometric space. In this paradigm, "memory optimization" and "reducing RAM footprint" are placed close together, facilitating retrieval even in the absence of shared vocabulary.
\begin{itemize}
    \item \textbf{Embedding Models:} Large language models (e.g., Sentence Transformers) form the engine of this process, encoding input text into fixed-length vectors that preserve semantic relationships \cite{nie2025textembeddingmeetslarge}.
    \item \textbf{Vector Databases:} Specialized storage engines (such as Chroma or FAISS) are designed to index these embeddings efficiently. They enable "Nearest Neighbor" searches at scale, allowing an agent to scan millions of documentation chunks in milliseconds to find the most relevant context for a specific hardware constraint \cite{ma2025comprehensivesurveyvectordatabase}.
\end{itemize}

\subsection{Retrieval-Augmented Generation (RAG)}
Retrieval-Augmented Generation (RAG) is the architectural pattern that bridges the gap between a model's frozen weights and the need for up-to-date accuracy. It addresses the twin problems of "knowledge cutoff" and "hallucination" by effectively giving the LLM an "open-book" capability, where it can verify its answers against retrieved text \cite{gao2024retrieval}.

A reliable RAG pipeline for engineering workflows typically involves:
\begin{enumerate}
    \item \textbf{Indexing:} Technical documents are ingested, cleaned (e.g., removing HTML tags), and segmented into manageable "chunks." These chunks are then embedded and indexed. The granularity of chunking is critical to balance context preservation with retrieval precision.
    \item \textbf{Retrieval:} Upon receiving a user query (e.g., "How to map float32 to INT8 on STM32H7?"), the system performs a similarity search against the index to retrieve the top-$k$ most relevant document segments.
    \item \textbf{Generation:} The retrieved context is injected into the LLM's prompt via a structured template. The model then synthesizes a final answer, conditioned on both its internal parametric knowledge and the non-parametric external evidence \cite{lewis2020retrieval}.
\end{enumerate}

\subsection{Web Research and Hardware Knowledge Grounding}
Beyond static documents, modern retrieval frameworks integrate an active "Web Research" component. The agent can perform live lookups for real-time data, such as software patches, by utilizing search APIs (e.g., Google Search). This dynamic grounding is necessary for making operational decisions that remain valid over time.

\subsection{Challenges and Bias Mitigation}
Despite its utility, RAG introduces specific failure modes. "Retriever failure" can occur if the embeddings fail to align the query with the correct document, often due to domain mismatch (e.g., general English embeddings used on highly technical datasheets). However, "Generator failure" happens when the LLM prioritizes its training data over the retrieved context, a phenomenon known as \textit{hallucination despite retrieval} \cite{Gao2024RetrievalAugmentedGN}. To mitigate these, systems often employ "Self-Correction" loops, where the agent critiques its own generated code against the documentation before searching again, ensuring that the final output is technically sound.
