ARCHITETTURA CLOUD PER LANGGRAPH - SCALABILITÀ E PERSISTENZA
================================================================

## 1. NECESSITÀ DI SCALABILITÀ

L'obiettivo è gestire carichi di lavoro variabili in modo efficiente.

### Scalabilità Orizzontale
- Si parte con risorse minime (CPU, RAM, GPU) per evitare sprechi ("cold start")
- Quando il traffico aumenta (da pochi a 100+ utenti), si creano istanze aggiuntive
- Le istanze condividono il traffico (es. 50%-50%)
- Terminato il picco, le istanze extra vengono rimosse
- Gestione dinamica tramite Kubernetes basata su soglie di traffico


## 2. PROBLEMA: PERDITA DI CONTESTO TRA ISTANZE

### Isolamento delle Istanze
Ogni istanza LangGraph opera come processo separato con proprio database/cache locale.

### Il Thread è Locale
- Il "thread" (contesto + stato conversazione) vive solo su una macchina
- Se utente inizia su Istanza 1, la richiesta successiva su Istanza 2 perde tutto
- Non è possibile duplicare thread tra istanze (troppo complesso)
- GPU ottimizzano calcoli in base agli input: risultati leggermente diversi tra istanze


## 3. SOLUZIONE: REDIS CENTRALIZZATO

### Database in RAM Centralizzato
- Tutte le istanze si collegano a un Redis centralizzato
- Lo stato viene serializzato in JSON e salvato su Redis
- Associazione tramite chiavi: user_id + session_id (evita cross-talking)
- Ogni istanza recupera lo stato da Redis tramite Thread ID

### Persistenza a Lungo Termine
- Redis gestisce solo sessioni attive (RAM costosa)
- Dopo inattività (es. 2 giorni), stato spostato a Postgres
- Per semplicità iniziale: stati vecchi vengono eliminati


## 4. IDEMPOTENZA: CONCETTO CHIAVE

### Definizione
Il servizio deve produrre output identico indipendentemente dall'istanza usata.

### Implementazione
- LangGraph diventa "stateless": non salva nulla localmente
- Genera risposte basandosi solo su input + contesto esterno
- Permette creare/distruggere istanze senza interrompere l'esperienza utente


## 5. CONTEXT ASSEMBLER

### Ruolo
Servizio leggero che fa da intermediario tra client e LangGraph.

### Flusso
1. Legge stato da Redis
2. Assembla prompt con contesto (summary, ultimi messaggi)
3. Invia a LangGraph
4. Riceve risposta
5. Aggiorna stato su Redis


## 6. ARCHIVIAZIONE FILE: S3 E MINIO

### Amazon S3 (Produzione)
- Storage persistente per file di progetto (firmware, modelli)
- Organizzato in "bucket"
- Ogni file accessibile tramite URL specifico

### MinIO (Sviluppo Locale)
- Simula comportamento S3 in container Docker
- Compatibile con API S3
- Ideale per test locali


## 7. SICUREZZA E CONTROLLO ACCESSI

### JWT Token
- Ogni utente ha token JWT associato alla sessione
- Token contiene user_id

### Autorizzazione
- Sistema verifica se user_id nel JWT può accedere a path nel bucket
- Esempio path: /user/{user_id}/session/{session_id}/
- Accesso non autorizzato: errore 403 Forbidden


## 8. FLUSSO DI LAVORO CON VS CODE

### Durante Pipeline Attiva
- Utente rimane connesso alla STESSA istanza per gestire interrupt
- Interrupt: richieste di input tipo "vuoi colore giallo o verde?"

### Fine Pipeline
- Sistema rileva nodo finale ("End") del grafo
- VS Code chiama servizio per salvare stato completo su Redis
- Flag `is_finished` basato sul nome del nodo

### Nuove Richieste
1. Client recupera stato precedente da Redis
2. Passa stato a NUOVA istanza di LangGraph
3. Istanza riprende contesto correttamente


## 9. STRATEGIE DI OTTIMIZZAZIONE REDIS

### Cosa Salvare
Opzioni valutate:
- Stato completo (pesante ma completo)
- Summary ultimi N messaggi (leggero ma parziale)

### Lock per Concorrenza
- Implementare lock in Redis per singole sessioni
- Evita conflitti quando più processi accedono stesso stato


## 10. PRIORITÀ DI IMPLEMENTAZIONE

### Fase 1 - Alta Priorità
1. Integrazione VS Code con LangGraph
2. Gestione sessioni e interrupt
3. Salvataggio stato su Redis al termine pipeline
4. Serializzazione JSON dello stato
5. Lock in Redis per concorrenza

### Fase 2 - Bassa Priorità
1. Storage persistente file su S3/MinIO
2. Storico chat in Postgres
3. Gestione granulare bucket per utente
4. Migrazione automatica Redis → Postgres per sessioni vecchie


## 11. TECNOLOGIE COINVOLTE

- **LangGraph**: Orchestrazione workflow AI
- **Redis**: Cache in-memory per stato attivo
- **Postgres**: Database per storico (futuro)
- **Amazon S3 / MinIO**: Object storage per file
- **Docker**: Containerizzazione
- **Kubernetes**: Orchestrazione scalabilità
- **JWT**: Autenticazione e autorizzazione
- **FastAPI**: API server Python


## 12. VANTAGGI ARCHITETTURA

1. **Scalabilità**: Aggiungi/rimuovi istanze dinamicamente
2. **Affidabilità**: Stato centralizzato, no perdita dati
3. **Performance**: Redis ultraveloce per accesso stato
4. **Sicurezza**: JWT + controllo accessi granulare
5. **Develop/Production Parity**: MinIO locale = S3 remoto
